04How to write an answer that gets full marks

The course's own answer template (the 10 Minute School case) shows the pattern. Use it every time.

1 Define the concept (exact words)→2 Point to the problem in the case→3 Say how the concept fixes it→4 Put it in a table when you compare
ConceptDefinitionProblem in the caseHow it fixes it
FirmnessA program should have no bugs that inhibit its function.Students cannot track course progress: a core function is broken.Reliable progress tracking saved to the server; no crashes, no data loss on logout.

For calculations

Write the formula, substitute the values, compute, then one sentence on what the number means. The project rules say a correct number with no working gets no accuracy marks; examiners mark the same way.

For "choose a model / strategy"

Name it, give two reasons tied to facts in the case, and say why the closest alternative is worse. The slides say marks go to the reasoning, not the label.

Common ways to lose marks
  • A definition with no link to the scenario.
  • Generic advice ("do more testing") without naming which test and why.
  • Forgetting units (pm, weeks, BDT lakh) or rounding sprints down.
  • Ranking risks by probability or by impact alone instead of RE.
  • Writing "agile has no documentation". The right-hand items still have value.

07Exam-day checklist

  • Calculator with log and square root (log2 x = ln x / ln 2).
  • Memorised: IEEE SE definition, four manifesto values, five XP values, three golden rules, baseline definition.
  • Memorised numbers: 1/5/10/20/150; 20/48/16/16; COCOMO coefficients; FP weights; Z = 1.645.
  • Read the case twice and underline every number and every Bangladeshi company detail.
  • Plan time: about 3 minutes per mark on a 90-minute, 30-mark paper.
  • For each answer: define, apply to the case, fix, table if comparing.
  • Show formula, substitution, result and meaning for every calculation.
  • Leave 5 minutes to check units, rounding and that every sub-part is answered.
